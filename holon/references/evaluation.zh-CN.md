# 测量这棵树到底有没有用

[English](evaluation.md)

`replay` 只能说明一棵树和它自己的词模型一致。它说明不了：agent 是否按同样的路径走，是否比平铺的文件夹更常选对 skill，是否用更少的上下文完成任务。这一页写的是怎么测这些，好让不同人的结果能互相比较。目前还没有发布过结果。

## 比什么

同一批 skill 的三种摆法，用来把"树"的作用和"正文变短"的作用分开：

| 摆法 | 是什么 |
|---|---|
| A. 平铺，原样 | 每个 skill 保持拿来时的样子，平放在一个 skills 文件夹里 |
| B. 平铺，精简 | 正文和树里的一样（背景材料已移进 `references/`），但仍然平放 |
| C. holon 树 | 同一批 skill，按 organizer 的规则放好，作为一个根安装 |

B 减 A 是规则 2（把知识移出正文）的作用；C 减 B 才是树本身的作用。设计记录 §17 显示，目前测到的节省大部分属于 B 减 A。

## 测试句子

- 每个库至少 50 句，由没有参与放置 skill 的人写。来自 `_feedback.md`、issue、聊天记录的句子都算；放置 skill 时写的句子不算。
- 在修改覆盖词或 `synonyms.md` 之前先把句子定下来。用来调树的句子移到调参集，不计入结果。
- 有意包含：不含任何覆盖词的改写、第二种语言、否定句（"不要……"）、需要两个 skill 的句子、一句话里两个独立任务。
- 每句在运行之前先记下人认为应该用哪个（或哪几个）skill。

## 每次运行记录什么

| 字段 | 含义 |
|---|---|
| `host`、`model` | 例如 Claude Code 加某个模型、Codex、Cursor |
| `arrangement` | A、B 或 C |
| `files_read` | agent 打开过的每个 `SKILL.md` 和参考文件，按顺序 |
| `chosen` | 它实际照着做的那个 skill |
| `route_ok` | `chosen` 属于预期的 skill |
| `task_ok` | 任务结果通过事先写好的检查 |
| `input_tokens` | 工具报告的数字，算整个任务，不只是路由 |
| `wall_time`、`retries` | 实际观察到的 |
| `word_model` | 同一句话在 C 上运行 `organizer_cli.py route` 的结果 |

每句、每种摆法、每个模型至少跑三次，因为 agent 的结果不是确定的。

## 报告什么

- 每种摆法的 `route_ok` 和 `task_ok` 比例，以及运行次数。
- 每种摆法每个任务的 token，给中位数和分布。
- 在 C 上：agent 的路径和 `word_model` 一致的比例；不一致时，哪一边是对的。这个数字说明在那个工具上 `replay` 通过到底有没有意义。
- 失败的句子，原文照录。

专门用来让 agent 跑任务并给结果打分的工具，例如 [skillgrade](https://github.com/mgechev/skillgrade)，可以用来执行这些运行；这一页只规定比什么、数什么。

## 提交结果

开一个 issue，附上：上面那张表的 CSV、句子文件、技能库（不能公开就写一段说明）、工具和模型的版本、日期。证明树没有用的结果，和证明它有用的结果一样有价值。
